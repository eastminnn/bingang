# 빈강 요구사항 명세 (SRS)

> 범위: 1단계 앱 MVP · 최종 수정 2026-10-28 · 화면 시안 `design/app.html`

## 1. 개요

영남대학교의 **지금 비어 있는 강의실**을 보여 주는 웹 서비스. 실사용자가 있는 서비스를 운영하며 인프라·모니터링을 연습하는 것이 목적이다.

| 단계 | 내용 |
|---|---|
| **1. 앱 MVP** | API + DB + 화면 + 실데이터 수집, 로컬 Docker Compose |
| 2. 배포 | Oracle Cloud A1(arm64), Caddy HTTPS, GitHub Actions |
| 3. 모니터링 | Prometheus · Grafana · Loki, 디스코드 알림 |

## 2. 기능 요구사항

### 빈 강의실 탭

| ID | 요구사항 |
|---|---|
| F-1 | 건물을 먼저 고른다. 건물 이름·코드 검색, 즐겨찾기, 최근 본 건물(최대 5개), 구역(A~G)별 목록을 제공한다 |
| F-2 | 건물 목록에 건물마다 지금 빈 강의실 수를 보여 준다 |
| F-3 | 건물을 고르면 그 건물의 강의실을 호 순서로 정렬하고 층별로 묶어 보여 준다. 처음에는 **빈 곳만** 보이고, 끄면 사용 중인 강의실도 보인다 |
| F-4 | 기준 시각은 기본이 "지금"이고, 요일(월~금)과 시각(30분 단위, 09:00–21:00)으로 바꿀 수 있다 |
| F-5 | 강의실 상태 문구: 비어 있으면 `11:30까지 비어 있어요` + 남은 시간, 그날 남은 수업이 없으면 `오늘 끝까지 비어 있음`, 사용 중이면 `13:00부터 비어요` |
| F-6 | 강의실마다 09–21시 하루 타임라인 막대를 보여 준다 (수업 = 회색, 빈 시간 = 연한 초록, 지금부터 이어지는 빈 시간 = 초록, 기준 시각 = 세로선) |
| F-7 | 건물을 즐겨찾기에 넣고 뺄 수 있다 (건물 목록과 건물 화면 양쪽에서) |

### 학사 일정 탭

| ID | 요구사항 |
|---|---|
| F-8 | 이번 학기 학사 일정을 달별로 보여 준다. 지난 일정은 흐리게, 진행 중은 `진행 중`, 다가올 일정은 `D-n` |
| F-9 | 맨 위에 다음(또는 진행 중인) 일정을 크게 보여 준다 |
| F-10 | 행정용 항목(`학기개시일(n일)`)은 숨기고, 보강일 제목은 줄여 보여 준다. 예: `공휴일수업대체지정일(09.24.(목) 추석연휴일)` → `목요일 수업 (추석 보강)` |

### 공통

| ID | 요구사항 |
|---|---|
| F-11 | 하단 탭(빈 강의실 / 학사 일정). 탭을 오가도 보던 건물을 유지한다 |
| F-12 | 다크 모드: 시스템 설정을 따르고, 직접 전환하면 그 선택을 기억한다 |
| F-13 | 첫 진입 시 스플래시를 보여 준다 (같은 탭에서 다시 열면 짧게) |
| F-14 | 즐겨찾기·최근 본 건물·테마는 브라우저에 저장한다 (로그인 없음) |

### "비어 있음" 판정

- 시각 `t`, 요일 `d`에 `start_time <= t < end_time`인 수업이 없으면 빈 강의실이다. 수업이 끝나는 정각은 비어 있는 것으로 본다.
- 시각과 요일은 항상 `Asia/Seoul` 기준이다.
- **보강일**: 학사일정에 `공휴일수업대체지정일(… (목) …)`이 있는 날은 그날 요일 대신 **지정된 요일의 시간표**로 판정한다.
- 맞닿거나 겹치는 수업(연강)은 하나로 이어서 본다. 사용 중이면 이어진 수업이 모두 끝나는 시각부터 빈다.
- 수업 데이터가 없는 요일·시간(일요일 등)에는 비어 있다. 토요일 수업도 학교 시간표에 있으면 그대로 반영한다.

### 제외 (이후)

강의실 상세(하루 시간표), 공휴일·시험 기간의 휴강 반영, 시험 기간 안내 배너, 건물 지도·위치 기반 선택, 로그인, AI 기능.

## 3. API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/buildings?at=` | 건물 목록 + 건물별 빈 강의실 수 |
| GET | `/api/buildings/{code}/rooms?at=` | 그 건물의 모든 강의실 상태와 그날 수업 시간 (빈 곳만 보기는 화면에서 거름) |
| GET | `/api/academic-events?from=&to=` | 학사 일정 |
| GET | `/actuator/health` | 헬스 체크 |

`at`은 ISO-8601 시각(예: `2026-10-28T14:30:00+09:00`)이며, 생략하면 현재 시각이다. 쿼리 문자열에서는 `+`를 `%2B`로 인코딩한다(`encodeURIComponent`). 어느 시간대로 보내도 응답은 `+09:00`이다.

```json
// GET /api/buildings?at=2026-10-28T11:10:00%2B09:00  (숨긴 건물 제외, 코드 순서)
{
  "at": "2026-10-28T11:10:00+09:00",
  "buildings": [
    { "code": "B03", "name": "인문관", "zone": "B", "freeRooms": 12, "totalRooms": 30 }
  ]
}
```

```json
// GET /api/buildings/B03/rooms?at=2026-10-28T11:10:00+09:00
{
  "at": "2026-10-28T11:10:00+09:00",
  "dayOfWeek": 3,
  "building": { "code": "B03", "name": "인문관" },
  "rooms": [
    { "number": "102", "floor": 1, "capacity": 80,
      "busy": false, "freeUntil": "11:30", "freeAt": null,
      "sessions": [["09:00","10:15"], ["11:30","14:00"]] },
    { "number": "106", "floor": 1, "capacity": 120,
      "busy": true, "freeUntil": null, "freeAt": "13:00",
      "sessions": [["10:30","13:00"]] }
  ]
}
```

- `dayOfWeek`: 판정에 실제로 쓴 요일이다 (보강일이면 지정된 요일).
- 강의실은 호수 숫자 순서이고, `sessions`는 연강을 합친 그날 수업이다.

```json
// GET /api/academic-events?from=2026-12-01&to=2026-12-31  (기간과 겹치는 일정, 시작일 순)
{
  "from": "2026-12-01", "to": "2026-12-31",
  "events": [
    { "startDate": "2026-12-08", "endDate": "2026-12-08",
      "title": "공휴일수업대체지정일(09.24.(목) 추석연휴일)", "substituteDay": 4 }
  ]
}
```

- `from`·`to`를 생략하면 오늘 기준 앞뒤 6개월이다. 시작일이 종료일보다 늦거나 기간이 1년을 넘으면 `400 INVALID_DATE_RANGE`.
- 오류: 잘못된 파라미터는 `400`, 없는(또는 숨긴) 건물은 `404 BUILDING_NOT_FOUND`이다. 모든 오류는 같은 형식으로 응답하고, `500`에는 내부 메시지를 넣지 않는다.

```json
{ "status": 400, "code": "INVALID_PARAMETER_TYPE", "message": "요청값 형식이 올바르지 않습니다.",
  "errors": [{ "field": "at", "message": "형식이 올바르지 않습니다." }] }
```

## 4. 데이터 출처

| 데이터 | 출처 | 방식 |
|---|---|---|
| 건물·강의실 | 학생종합정보시스템 '빈강의실조회' 응답 (학교 시스템 코드, 예: B03 인문관) | 시간표 수집 때 함께 저장 |
| 강의 시간표 | 학생종합정보시스템 '빈강의실조회' (로그인 필요, 사용 허락 받음) | 수집기가 학기 초 1회 + 주 1회, 요일 × 교시별로 빈 강의실을 조회하고 뒤집어 `room_schedule`에 저장 |
| 학사 일정 | `https://www.yu.ac.kr/main/bachelor/calendar.do` (로그인 불필요) | 페이지 HTML에 들어 있는 `calData` JSON을 하루 1회(05:00) 수집, `articleNo` 기준 upsert. 테이블이 비어 있으면 앱 시작 때 바로 1회 |

## 5. 비기능 요구사항

| ID | 요구사항 |
|---|---|
| N-1 | `docker compose up -d` 한 번으로 전체가 실행된다 |
| N-2 | arm64(Mac M3, Oracle A1)에서 동작한다 |
| N-3 | 모바일 우선(360px), 다크 모드 지원. 디자인 규칙: 간격 4·8·12·16·24, 글자 13·15·17·22, 굵기 400·600, 모서리 8, 강조색은 "빈 시간" 초록 하나 |
| N-4 | 비밀값은 `.env`로 분리하고, 저장소에는 `.env.example`만 커밋한다 |
| N-5 | 판정 로직은 단위 테스트로, API·DB는 Testcontainers 통합 테스트로 검증한다 |
| N-6 | 학사일정 수집은 하루 1회만 한다. 실패하면 마지막으로 저장한 데이터를 유지하고, 3단계에서 알림을 보낸다 |
| N-7 | 사용자 요청은 DB만 조회하고 학교 시스템으로 넘기지 않는다. 수집 요청은 1초에 1건 이하로 보낸다 |
| N-8 | 학교 계정 정보는 서버 환경 변수(`.env`, GitHub Secrets)에만 두고 저장소·로그에 남기지 않는다. 저장소는 비공개로 둔다 |
| N-9 | 초당 100건에서 p95 200ms 이하, 에러율 1% 미만 (추정 피크 초당 약 10건의 10배). 3단계에서 k6로 검증한다 |
